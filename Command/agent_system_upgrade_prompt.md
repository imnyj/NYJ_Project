# 에이전트 시스템 업그레이드 프롬프트

## 시스템 핵심 구조

작업을 로컬 모델이 수행할 수 있는 수준으로 완전히 작게 쪼개고 각 단위마다 에이전트를 할당하여 유기적으로 협업하는 시스템을 구축한다

## 작업의 원자화 프로세스와 컨텍스트 유지

주어진 작업을 여러 하위 단계로 세분화한다
첫 번째 단계로 큰 틀의 작업을 나눈다
시뮬레이션 그래프 제작을 예로 들면 모델 관리와 그래프별 관리 그리고 표현 관리 등으로 분류한다
두 번째 단계로 각 분류를 더 세부적으로 나눈다
모델 관리의 경우 비교 방안 1과 비교 방안 2 그리고 모델 추가 및 제거 관리 등으로 세분화한다
세 번째 단계로 비교 방안 1을 다시 추론과 훈련 그리고 인코더와 디코더 등으로 더 작게 분할한다
작업이 여전히 복잡하다면 네 번째 단계로 계속해서 쪼갠다

각 단계에서 세분화된 작업이 있는 경우 계속해서 다음 단계로 쪼갠다
이렇게 쪼개진 모든 단위의 작업마다 전담 에이전트를 배치하고 운용한다

상위 에이전트는 하위 에이전트에게 세부 작업을 지시할 때 프로젝트 전체의 요약본과 구체적인 체크리스트를 함께 전달해야 한다
하위 에이전트는 요약본을 통해 자신의 역할이 전체 그림에서 어떤 위치인지 파악하고 체크리스트에 명시된 부분만 확실하게 수행한다
작업을 마치면 상위 에이전트에게 보고하고 검수를 받는 하청 형태의 구조를 구축하여 작업의 누락을 방지하고 일관성을 유지한다

## 재귀적 작업 분할과 하위 에이전트 생성 승인

개별 에이전트가 상위 계층으로부터 새로운 작업 요청을 받았을 때 그 규모와 복잡도를 스스로 판단하도록 규칙을 부여한다
주어진 작업이 혼자서 처리하기에 너무 크거나 복잡하다고 판단되면 직속 상위 에이전트에게 새로운 하위 계층 생성을 요청해야 한다
상위 에이전트는 그 사유가 합리적인 경우에만 생성을 승인하며 승인된 경우에만 새로운 에이전트들을 생성하여 작업을 다시 분배한다
이를 통해 무분별한 에이전트 파생을 막고 시스템 내의 작업 원자화 원칙이 안정적으로 유지되도록 만든다

## GUI 기반 에이전트 제어와 다중 세션 관리

사용자는 웹 프론트엔드로 구현된 시각적인 화면을 통해 전체 시스템을 제어할 수 있어야 한다
첫 화면에서는 전체 프로젝트 세션을 조회하고 선택하거나 새 프로젝트를 생성하고 이름을 변경할 수 있도록 구성한다
프로젝트에 진입한 후에는 좌측에 계층을 나타내는 버튼 트리와 중앙에 대화 창 그리고 우측에 세션 이력을 배치한다
하위 에이전트를 생성할 때는 전반적인 흐름과 최종 목적을 명확히 전달하며 모델의 기억 용량을 초과하지 않도록 여러 세션을 열어 분할 작업하도록 강제한다
각 에이전트는 자신에게 할당된 대화 횟수와 작업 내역을 세션 단위로 기록하여 언제든 이전 세션에 이어서 작업을 진행할 수 있도록 지원한다

## 웹 서비스 연동 아키텍처

로컬 환경에서 동작하는 에이전트 로직은 백엔드 서버로 감싸고 통신 규약을 통해 웹 프론트엔드와 연결한다
사용자가 화면에서 특정 하위 에이전트에게 지시를 내리면 서버가 이를 받아 담당 에이전트를 호출하고 결과를 화면으로 반환한다
이 구조를 통해 터미널 환경의 제약을 극복하고 독립적인 에이전트 관리 웹 서비스를 구축한다

## 메모리 운용과 정보 공유 및 스케줄링

작업한 모든 내용은 프로젝트 내의 다른 에이전트들과 공유한다
각 에이전트는 이전 세션의 작업 맥락을 끊김 없이 이어갈 수 있도록 자체적인 메모리와 두뇌 시스템을 운용한다

독립적인 두뇌를 가지면서 발생하는 동시 접근 충돌을 막기 위해 파일 잠금 스케줄링 프로토콜을 도입한다
다수의 파일 잠금 과정에서 발생할 수 있는 교착 상태를 예방하기 위해 잠금 순서와 권한을 관리하는 중앙 통제 규약을 강제한다
에이전트가 특정 파일을 수정하기 전에는 반드시 작업 공간의 스냅샷을 자동으로 백업하여 언제든 복구할 수 있는 안전장치를 마련한다
에이전트가 파일을 수정할 때는 다른 에이전트가 접근하지 못하도록 잠금 상태로 만들며 대기 시간이 길어지더라도 끝까지 작업을 완료할 수 있도록 제한 시간을 넉넉하게 부여한다
작업이 완전히 끝난 후에만 잠금을 해제하여 정보가 엉키는 현상을 원천적으로 차단한다

## 에이전트 팩토리와 역할 부여

하위 에이전트는 상위 에이전트에 의해 필요할 때마다 생성된다
이때 용도에 맞는 역할에 따라 에이전트 팩토리에서 만들어진다
각 역할로 준비된 에이전트 틀에는 역할마다 고유하게 부여된 절대 룰을 엄격하게 적용한다

## 절대 룰 관리와 MD 파일 접근성

역할에 대한 절대 룰은 사용자의 피드백을 지속적으로 반영하여 업데이트한다
절대 룰은 MD 파일 형태로 운용하며 사용자가 원할 때 언제든 직접 내용을 바꿀 수 있도록 접근 및 수정 권한을 허용한다

## 상위 에이전트 전담 검토 시스템

담당 작업을 완료하면 직속 상위 에이전트 또는 크리틱 에이전트가 하위 에이전트의 작업 결과물을 검토한다
담당 작업을 완료하면 직속 상위 에이전트에게 보고하며 상위 에이전트는 기존 세션의 맥락을 보호하기 위해 완전히 새로운 세션을 열어 결과물을 검증한다
수정이 필요하면 상위 에이전트가 어떻게 수정해야 하는지 구체적인 방향을 추천해준다
검증이 완료될 때까지 이 과정을 반복하며 승인이 끝난 후에만 최종 작업으로 인정한다

## 계층적 결재 구조

최상위 에이전트가 모든 세부 사항을 일일이 확인하면 과부하가 걸리고 전체 시스템이 크게 지연된다
이를 해결하기 위해 직속 상위 에이전트가 하위 에이전트의 결과물을 체크리스트 기반으로 일차적으로 검수한다
최상위 에이전트는 최종 산출물들이 서로 올바르게 결합되었는지만 확인하는 피라미드 형태의 결재 구조를 갖춘다

## 작업 로그 기록과 책임 추적 시스템

수많은 에이전트가 참여하는 환경에서 오류가 발생했을 때 책임 소재를 명확히 하기 위해 작업 로그를 남긴다
각 에이전트가 작업을 마칠 때 자신의 식별자와 수정한 파일명 그리고 수행한 작업 내용을 공통 로그 파일에 기록하도록 강제한다
이후 문제가 발견되면 상위 에이전트가 이 로그를 역추적하여 해당 작업을 수행했던 에이전트의 환경을 재구성한다
문제를 일으킨 에이전트에게 오류 내역과 당시 로그를 다시 전달하여 스스로 책임지고 수정하도록 지시한다

## SSH 재연결 및 입력 예외 처리

SSH 세션 끊김 현상 등으로 인해 자동으로 입력되는 `source /home/imnyj/venv/bin/activate` 명령은 셸 도구 실행이나 대화 맥락에 영향이 없도록 무시한다. 에이전트는 이를 감지하더라도 가상환경을 반복해서 켜는 등 불필요한 행위를 하지 않고, 직전에 진행 중이던 원래 작업 흐름을 유지한다.
