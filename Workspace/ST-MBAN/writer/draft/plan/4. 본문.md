# 4.1 Content Request and Feature Extraction
차량은 원하는 content가 발생하면, RSU 통신 범위 내에 위치할 경우 즉각적으로 interest packet을 전송하여 content를 요청함.
RSU 통신 범위 밖인 경우 대기 상태를 유지함.
interest packet에는 차량 ID, content ID, 차량의 위치, 속도, 앞 차량과의 간격, 필요 차선 변경 횟수, 다음 RSU까지의 경로, 요청된 content의 요청 시작 청크 번호가 포함됨.
RSU는 해당 패킷을 수신한 후 CCN 절차에 따라 content 제공을 개시함.
동시에, RSU는 수신한 정보를 바탕으로 pending data table(PDT)에 차량 ID와 content ID를 key 값으로 하여 차량의 위치, 속도를 기록함.
이때 RSU는 즉시 입력 가능한 정보인 신호등 상태, 신호 변경 잔여 시간, 통신 범위 내 차량들의 평균 속도, RSU의 통신 반경을 PDT에 추가함.
더불어 위치와 속도를 바탕으로 산출한 RSU 중심점까지의 거리($d_{rsu}$) 및 예상 도달 시간($t_{est}$)을 계산하여 PDT에 기입함.
또한 차량의 이동 방향을 구분하여 기록함: 차량이 신호등에 설치된 RSU를 기 통과한 경우(RSU로부터 멀어지는 방향)는 1, 통과 이전인 경우(RSU로 접근하는 방향)는 0으로 표기함.
요청 차량이 소속된 차선(lane)을 식별하여 앞 차량의 순간/평균 속도, 요청 차량 전방의 차량 수, 해당 차선의 대기열(queue) 길이 및 점유율을 수집함.
이후 차량 경로 정보를 바탕으로 현재 RSU 범위 내 체류 잔여 거리, 다음 RSU 진입 시점까지의 거리, 다음 RSU 이탈 시점까지의 거리를 산출하여 PDT에 갱신함.
비콘 메시지 기반 평균 차량 속도 관리 메커니즘을 통해, 아직 집계되지 않은 통신 범위 내 체류 차량 대수를 파악하여 PDT에 반영함.

다음 RSU로부터 추가 정보를 획득하기 위해 `[INFO REQ]` 패킷을 송신함.
해당 패킷에는 현재 RSU ID, 차량 ID, content ID가 포함됨.
`[INFO REQ]` 패킷을 수신한 다음 RSU는 pending request table에 해당 패킷을 등록함.
다음 RSU는 수신 확인 후, 패킷의 RSU ID를 자신의 ID로 갱신하여 이웃 RSU들에게 `[INFO HELLO]` 패킷 형태로 브로드캐스트함.
`[INFO HELLO]` 패킷을 수신한 이웃 RSU는 평균 속도 관리 테이블을 참조하여, 차량 중 다음 RSU ID를 목적지로 가지며 이웃 교차로 등에서 해당 경로로 진입/병합이 예상되는 차량 수($n_{merge,nxt}$)를 집계하고, 요청 차량 ID 및 content ID와 함께 `[INFO REP]` 패킷을 통해 다음 RSU로 회신함.
동시에 다음 RSU는 자체적으로 보유한 신호등 상태, 신호 변경 잔여 시간, 평균 차량 속도, 요청 차량 진입 방향 차선의 대기열 길이 및 점유율, 그리고 해당 차량이 진입할 경로상의 선행 차량 수($n_{ahead,nxt}$)를 산출함. 
이후 이웃 RSU로부터 수신한 $n_{merge,nxt}$를 취합하여, pending request table에 저장된 원래의 요청 RSU ID를 목적지로 삼아 `[INFO REP]` 패킷을 송신(회신)함.
최종적으로 초기 요청 RSU가 수신하는 `[INFO REP]` 패킷에는 다음 RSU의 평균 차량 속도, 통신 범위 내 차량 수, 신호등 상태, 신호 변경 잔여 시간, 해당 차량 경로상의 선행 차량 수($n_{ahead,nxt}$), 그리고 이웃 RSU로부터 진입이 예상되는 차량 수($n_{merge,nxt}$)가 포함됨.

(feature vector 정리한 표 추가)

초기 RSU는 수신한 `[INFO REP]` 패킷 데이터를 차량 ID와 content ID를 key로 하여 PDT에 병합함.
각 정보의 특성을 효과적으로 반영하기 위하여, 수집된 요소(element)들은 카테고리화(categorized)됨.
완성된 feature vector 및 각 요소의 카테고리는 표 1과 같이 정의됨.
Content 제공이 이루어지는 동안 소형 패킷 기반 snapshot 형태로 feature를 구성하므로, 시계열 기반 연속 생성 방식 대비 통신망 부하를 저감할 수 있음.
또한, content 데이터 전송과 feature 수집이 독립적으로 수행되므로 서비스 품질 저하를 방지함.
요소별 카테고리화를 통해 데이터 특성 반영의 효율을 높일 수 있음.
궁극적으로 중앙 서버 의존 없이 국소적(local) 정보 수집을 수행하여, 서버 병목 현상을 완화함.

# 4.2 H-ST-MBAN Architecture and Inference
RSU는 PDT에 수집 및 분류된 feature vector를 기반으로 next RSU에서 precaching해야 할 chunk들을 파악하기 위해서 통신 범위 체류 시간($t_{cur, dw}$)과 다음 통신 범위 체류 시간($t_{nxt, dw}$)을 추론한다. 이를 위해 본 논문은 V2I 환경의 높은 변동성과 이기종 센서 데이터의 특성을 반영하여 설계된 하이브리드 모델인 H-ST-MBAN을 제안한다.

먼저, 통신 인프라 구성 초기 등으로 인하여 RSU에 pre-trained H-ST-MBAN 모델이 없는 경우(Cold-Start), 범위 내 차량의 평균 속도를 기반으로 체류 시간을 단순 수식 계산하는 fallback 구조를 가진다. WAVE 표준에 따른 RSU의 통신 반경과 차량의 경로 정보를 기반으로 현 RSU로부터의 이탈까지 남은 거리, 다음 RSU의 진입/이탈 거리를 속도로 나누어 두 체류 시간을 추산한다. 단, 이 단계에서도 추후 학습을 위한 데이터 수집을 위해 PDT와 dataset queue는 정상적으로 운용된다. 

반면, pre-trained H-ST-MBAN 모델이 배포된 상태에서는 해당 모델을 통해 두 체류 시간을 정밀하게 추론한다. V2I 환경의 정형 데이터(Tabular data)는 이미지나 텍스트와 달리 동역학적, 공간적, 위상적 특성의 스케일이 제각각이며 극단적 이상치(예: 돌발 정체, 사고)가 빈번하게 발생한다. 기존의 단순 다층 퍼셉트론(MLP)이나 순환 신경망(RNN) 기반 접근법은 이러한 이기종 피처들을 단순히 이어 붙여(Concatenation) 처리함으로써, 스케일이 큰 특정 피처가 전체 학습을 지배하거나 기울기 소실/폭주 현상을 겪는 한계가 있었다. 더불어, 에지 컴퓨팅 환경에서의 온라인 파인튜닝 시 과거의 지식을 잊어버리는 치명적 망각(Catastrophic Forgetting) 현상이 발생하기 쉽다. 

H-ST-MBAN은 이러한 한계들을 극복하고 V2I 통신 시나리오 하에서의 예측 신뢰성을 극대화하기 위해, 피처 인코딩부터 어텐션 융합, 디코딩, 하이브리드 게이팅에 이르는 4가지 핵심 모듈과 기여점(Contributions)을 기반으로 동작하도록 설계되었다.

- **1. Heterogeneous Feature Extraction via Pre-activation ResBlocks (이기종 데이터 독립적 특징 추출):**
  - **설계 목적 및 의미:** 서로 다른 스케일을 가지는 Kinematic(동역학적), Topological(네트워크 위상 및 신호), Spatial(공간적 밀도)의 세 가지 도메인 피처들을 하나의 벡터로 단순 결합(Early Fusion)하지 않고, 각 도메인별로 독립적인 인코딩을 거치게 하는 늦은 융합(Late Fusion) 구조를 채택했다. 이는 데이터 고유의 특성이 훼손되는 것을 방지한다.
  - **설계 원리 및 기대 효과:** 특히 정형 데이터의 스케일 차이로 인한 학습 불안정을 막기 위해, 연산 전에 정규화를 먼저 수행하는 **Pre-activation Residual Block (`BatchNorm1d -> ReLU -> Linear`)** 구조를 적용했다. 이를 통해 기울기 소실 및 폭주를 예방하고, 서로 다른 특성의 데이터들을 통일된 잠재 공간 차원($d_{model}$)으로 안전하게 투영하여 모델의 표현력(representation capacity)을 극대화한다.

- **2. Domain-Level Multi-Head Attention Fusion (도메인 단위 어텐션 융합):**
  - **설계 목적 및 의미:** 독립적으로 인코딩된 3개의 도메인 피처를 각각 독립적인 토큰(Token)으로 취급하여, 시퀀스 형태로 Multi-Head Attention (MHA) 블록에 입력한다. 단순 결합 모델들이 갖지 못하는 '특성 간의 맥락 연관성'을 파악하기 위해 고안되었다.
  - **설계 원리 및 기대 효과:** 기존 딥러닝 기반 V2I 체류 시간 모델들이 단순히 피처 배열을 나열하여 분석하는 것과 달리, 본 모듈은 "신호등 상태(Topological)가 공간적 차량 밀도(Spatial)와 차량의 동역학적 속도(Kinematic)에 미치는 상호 의존성"을 어텐션 점수를 통해 동적으로 계산한다. 이를 통해 복잡한 위상적 제약 속에서의 차량 이동 맥락이 완벽히 반영된 융합(fused) 표현형을 도출하여 예측의 정확도를 대폭 향상시킨다.

- **3. Robust Deterministic Decoding against Outliers (이상치에 강건한 결정론적 디코딩):**
  - **설계 목적 및 의미:** MHA 블록을 거친 융합 벡터는 Flatten 처리된 후 다층 구조의 ResBlock 디코더를 통과하여 최종 체류 시간 값($t_{cur, dw}$, $t_{nxt, dw}$)으로 매핑된다. 콘텐츠 캐싱의 스케줄링을 신속하게 결정하기 위해서는 불확실성 범위가 아닌 높은 신뢰성의 점 추정치(point-estimate)가 필요하므로 결정론적(Deterministic) 모델을 채택했다.
  - **설계 원리 및 기대 효과:** 모델 훈련 시 회귀 문제의 일반적인 표준인 MSE(Mean Squared Error) 대신 **L1 Loss (MAE)**를 적용했다. 이는 센서 수집 과정의 노이즈나 돌발적인 교통 정체와 같은 극단적인 이상치(Outlier)가 발생했을 때 손실 값이 제곱으로 증폭되어 그래디언트를 오염시키는 현상을 방지한다. 변동성이 극심한 현업 도로 환경에서도 안정적인 학습과 추론이 보장된다.

- **4. Adaptive Residual Prior Learning (학습 가능한 적응형 하이브리드 게이팅):**
  - **설계 목적 및 의미:** 비선형 시공간 패턴 학습 능력이 뛰어난 심층 신경망(NN)과, 초기 수렴 안정성 및 일반화 역량이 뛰어난 머신러닝(ML) 트리 모델(예: XGBoost)의 추론 결과를 결합하기 위해 설계되었다.
  - **설계 원리 및 기대 효과:** 최종 예측값은 단순히 신경망 출력에 의존하지 않고, 두 모델의 결과물을 $\alpha \times \text{ML\_Pred} + \beta \times \text{NN\_Pred}$ 형태로 융합한다. 특히 $\alpha$와 $\beta$를 고정 상수가 아닌 역전파를 통해 업데이트되는 **학습 가능한 파라미터(Learnable Parameter)**로 설계하였다. 즉, 초기에는 ML 모델을 기준점(Anchor)으로 삼아 모델 붕괴를 원천 차단하고, 시간이 지나 데이터가 누적됨에 따라 모델 스스로 신경망(NN)의 가중치를 높이는 적응형 게이팅(Adaptive Gating)을 수행한다. 이는 엣지 노드에서의 실시간 온라인 파인튜닝 시 발생하는 발산 및 치명적 망각(Catastrophic Forgetting) 현상을 방어하는 H-ST-MBAN만의 독보적인 핵심 기여점이다.

# 4.3 Precaching Scheduling
계산 및 추론된 값을 기반으로 precaching 수행하는 절차
추론된 또는 계산된 $t_{cur, dw}$과 $t_{nxt, dw}$.
추론된 $t_{cur, dw}$을 기반으로 현재 RSU($R_{cur}$)는 평균 통신 속도($B_{avg}^{cur}$)를 기반으로 전달 가능한 총량을 계산.
이때 계산의 용이성뿐만 아니라, "라우터 Content Store의 메모리 단편화(Fragmentation) 방지로 인한 O(1) 캐시 관리 효율성 및 하위 계층 MTU(Maximum Transmission Unit) 한계로 인한 패킷 분할 방지"를 위해 CCN 단일 청크 크기($S_{chunk}$)는 모두 같다고 고정하여 가정함.
전달 가능한 청크 수($N_{cur, chunk}$)를 계산할 때는 통신 마진을 반영하는 적응형 안전 계수 $\eta$를 도입함.
$\eta$는 단순 상수가 아닌, 채널 환경에 동적으로 적응하도록 최근 평균 패킷 성공률($\bar{P}_{success}$)과 채널 SNR 분산($\sigma_{channel}^2$)을 반영하여 $\eta(t) = \alpha \cdot \bar{P}_{success}(t) - \beta \cdot f(\sigma_{channel}^2(t))$ 수식을 통해 결정됨.
최종적으로 $R_{cur}$가 전송 가능한 청크 수는 $N_{cur, chunk} = \lfloor \frac{\eta \cdot B_{avg}^{cur} \cdot t_{cur, dw}}{S_{chunk}} \rfloor$ 공식을 통해 산출.
요청된 시작 chunk no.를 기반으로 현 RSU에서 받을 수 있는 마지막 청크 번호를 계산.
$R_{cur}$는 다음 RSU($R_{nxt}$)에게 Precache Packet을 보냄.
해당 패킷에는 Content ID, 다음 청크의 번호, 추론된 $t_{nxt, dw}$가 포함됨.
해당 패킷을 받은 $R_{nxt}$는 받은 $t_{nxt, dw}$을 통해 같은 방식으로 전달 가능한 청크의 수를 계산.
다음 청크의 번호부터 precaching해야 할 청크들을 Interest packet을 통해 CCN의 절차에 따라 다운로드.
프리캐싱된 청크에는 자율주행 차량의 경로 이탈 등 예외 상황 시 라우터의 "PIT(Pending Interest Table) 고갈 마비(Exhaustion) 방지" 및 "잘못된 과거 정보(Stale data)에 의한 판단 오류 방지를 위한 Data Freshness 보장"을 위해 TTL(Time-To-Live) 기반 캐시 만료(Eviction) 정책을 적용하여 Cache Pollution을 방어함.

# 4.4 Result Reporting and Online Training
요청 차량은 $R_{cur}$를 나가면서 $R_{cur}$의 ID와 $t_{cur, dw}$의 정답값을 기록.
Interest Packet을 주기적으로 보내 Content 다운로드를 시도함.
$R_{nxt}$의 통신 범위에 진입했을 경우, Interest packet이 해당 RSU에게 전송되며, 이전 RSU에서의 과정과는 별도로 현재 RSU에서 또 다른 content provision process가 시작됨.
이 별도의 process는 서브섹션1부터 다시 시작함.
동시에 요청 차량은 $t_{nxt, dw}$을 측정하기 위한 타이머를 동작시키며, RSU로부터 precached chunk를 즉시 제공받을 수 있음.
오차로 인하여 precached되지 않은 chunk는 CCN의 절차에 의해 주위 RSU나 Content server로부터 받아와 짐.
이후 요청 차량은 지금 머무르고 있는 RSU로부터 벗어나며 $t_{nxt, dw}$을 집계함.
요청 차량은 차량의 ID, Content ID, RSU를 나가기 직전 저장되어 있던 이전 RSU의 ID, 측정된 $t_{cur, dw}$, $t_{nxt, dw}$을 포함한 Report Packet을 현 RSU에게 전달함.
해당 패킷을 받은 RSU는 RSU ID를 비교하고, 본인이 아닐 경우 RSU ID를 기반으로 해당 패킷을 포워딩함.
포워딩을 통해 Report packet을 받은 RSU는 PDT에 저장되어 있는 항목 중 차량 ID와 Content ID가 매칭 되는 항목을 검색.
해당 항목의 완성된 feature vector와 함께 $t_{cur, dw}$, $t_{nxt, dw}$을 묶어서 Ground Truth (Report) 데이터를 생성하고, 이를 RSU 내부의 로컬 데이터셋 큐(Dataset Queue)에 추가(accumulate)함. 
이후 시스템의 상태에 따라 다음과 같이 두 단계로 구분되어 모델 학습 및 업데이트가 진행됨:

- **초기 상태 (Pre-training; 서버 의존 단계):**
  도입 초기에는 RSU에 배포된 학습 모델이 존재하지 않으므로, RSU는 수집된 Ground Truth 데이터를 로컬 큐에 축적함. 큐의 데이터가 '충분히' 채워졌을 때에만 이를 배치(batch) 형태로 중앙 서버(Central Server)로 전송함. 중앙 서버는 RSU들로부터 수집된 대규모 데이터를 활용하여 글로벌 모델(Global Model)을 사전 학습(Pre-training)시킨 후, 완성된 초기 모델을 각 RSU로 배포함 (구체적인 사전 학습 데이터셋 규모는 5장 성능 평가 섹션에서 상세히 기술함).

- **운영 상태 (Online Fine-Tuning; 로컬 독립 단계):**
  사전 학습된 모델이 RSU에 배포된 이후에는, RSU가 중앙 서버에 완전히 독립적으로 동작함. RSU는 이전과 동일하게 로컬 큐에 데이터를 지속적으로 축적하지만, 이를 더 이상 서버로 전송하지 않음. 대신 RSU 자체의 엣지 컴퓨팅 리소스를 활용하여 로컬 데이터로 미세 조정(Fine-Tuning)을 수행함. 이를 통해 중앙 서버의 통신 부하를 없애고 지역적인 데이터 분포 변화(Local Concept Drift)에 즉각적이고 적응적으로 대응함 (미세 조정에 사용되는 구체적인 데이터 큐 크기 및 주기는 5장 성능 평가 섹션에서 상세히 기술함).
