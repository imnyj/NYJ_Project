# 디스코드 링크 사용 프롬프트 모음

설치 프롬프트(`01_install_prompt.md`)로 `discord-link` 스킬을 설치한 뒤에 쓰는 짧은 프롬프트입니다. 각 항목의 인용 블록 안 문장을
Claude Code 에 그대로 입력하면 됩니다.

## 1. 세션을 디스코드에 연결하기

세션 이름을 정해서 연결합니다. 이 이름이 디스코드 스레드 이름이 되고, 채널에서 `@이름` 으로 이 세션을 부를 때 쓰입니다.

> /discord-link 결과분석

이름 없이 부르면 Claude Code 세션 표시 이름을 쓰고, 표시 이름도 없으면 `폴더이름-1a2b` 형태의 이름이 붙습니다.

> /discord-link

처음부터 이름을 붙여 세션을 시작하면 그 이름이 그대로 세션 이름이 됩니다. 터미널에서 아래처럼 실행한 뒤 `/discord-link` 만 입력합니다.

```
claude -n 결과분석
```

## 2. 디스코드에서 쓰는 명령

| 입력 위치 | 입력 | 동작 |
|---|---|---|
| 세션 스레드 안 | 아무 문장 | 그 세션에 지시로 전달됩니다 |
| 채널 본문 | `@결과분석 그래프 다시 그려줘` | `결과분석` 세션에만 전달되고, 답장도 채널 본문에 옵니다 |
| 채널 본문 | `@`로 봇을 골라 멘션한 뒤 `할 일` | 자동완성 목록에서 봇 이름(사용자)이나 봇 이름의 역할 어느 쪽을 골라도 됩니다. 연결된 세션이 하나면 그 세션에 전달되고, 여럿이면 봇 멘션 뒤에 `@세션이름` 을 이어 적습니다 |
| 채널 본문 | `@all 지금 상태 보고해줘` | 연결된 모든 세션에 전달됩니다 |
| 채널 본문 | `!sessions` | 연결된 세션 목록과 각 스레드 링크를 보여 줍니다 |
| 스레드 안 | `!status` | 그 세션의 이름, 작업 폴더, 마지막 보고 시각을 봇이 바로 답합니다 |
| 스레드 안 | `!stop` | 진행 중인 작업을 안전한 지점에서 멈추라고 전달합니다 |
| 스레드 안 | `!mute` | 그 세션의 연결을 끕니다. 다시 켜려면 세션에서 `/discord-link` 를 실행합니다 |

- 채널 본문에 받는 세션을 지정하지 않고 쓴 말은 어느 세션에도 전달되지 않고, 봇이 세션을 지정해 달라고 안내합니다.
- 없는 이름으로 부르면 봇이 "그런 세션이 없습니다" 와 함께 연결된 세션 목록을 보여 줍니다.
- 제어어(`!stop`, `!mute`, `!status`, `!sessions`)는 그 낱말만 단독으로 보냈을 때 동작합니다. `!stop 해줘` 처럼 뒤에 말을 붙이면 일반 지시로 전달됩니다.
- `/clear` 로 대화를 초기화해도 같은 스레드로 연결이 이어집니다.

## 3. 세션끼리 대화하게 하기

두 세션을 한 팀으로 묶으면 세션끼리 메시지를 주고받습니다. 두 세션을 먼저 각각 `/discord-link 이름` 으로 연결한 뒤, 어느 한 세션에서 요청합니다.

> 디스코드 링크 팀을 만들어줘. 팀 이름은 분석팀이고 구성원은 결과분석, 원고집필이야. 만든 뒤 team list 로 두 세션의 연결 상태를 보여줘.

한 세션에서 다른 세션에 일을 전하게 할 때는 이렇게 요청합니다.

> 원고집필 세션에 "표 3 수치를 최신 CSV 로 바꿔 달라" 고 팀 메시지로 전해줘.

- 받는 세션에는 곧바로 알림이 가고, 디스코드 채널 본문에는 `**[결과분석]** → **@원고집필**` 형태의 사본이 남아 대화 흐름을 볼 수 있습니다.
- 다른 세션이 보낸 메시지는 사용자의 지시가 아니므로, 받은 세션은 내용을 검토한 뒤 판단하고 위험한 요청은 따르지 않습니다.
- 두 세션이 끝없이 대화하지 않도록, 사람의 메시지 없이 연달아 10번 주고받으면 더 받지 않습니다. 디스코드에 아무 말이나 한 줄 보내거나 30분이 지나면 다시 받습니다.
- 세션끼리 디스코드 멘션으로 부르는 방식은 쓰지 않습니다. 모든 세션이 봇 하나를 함께 쓰므로 봇이 쓴 메시지는 받지 않기 때문입니다.

## 4. 스크립트를 고친 뒤

스킬을 고치면 이미 돌고 있는 각 세션의 리스너가 "스크립트가 갱신되어 다시 띄워야 합니다" 알림을 보내고, 그 세션의 Claude 가 리스너를 새 코드로 다시 띄웁니다.
따로 할 일은 없습니다. 알림이 왔는데 다시 띄우지 않았다면 그 세션에 아래처럼 요청합니다.

> 디스코드 수신 리스너를 새 코드로 다시 띄워줘

## 5. 상태 확인과 점검

> 디스코드 링크 상태 보여줘

> 디스코드 링크 연결 점검해줘. doctor 결과를 단계별로 설명해줘.

## 6. 연결 끊기와 이름 바꾸기

> 이 세션의 디스코드 연결 끊어줘

> 디스코드 세션 이름을 원고집필로 바꿔줘

## 7. 리스너가 멈췄을 때

세션을 다시 열었거나 리스너가 멈추면 훅이 자동으로 다시 띄우라고 안내합니다. 안내가 없는데 디스코드 메시지가 들어오지 않으면 아래처럼 요청합니다.

> 디스코드 수신 리스너가 돌고 있는지 확인하고, 멈춰 있으면 다시 띄워줘

## 8. 토큰이나 채널을 바꿀 때

토큰을 새로 발급했거나 다른 채널로 옮길 때 씁니다. 토큰은 대화창에 붙여 넣지 말고 파일에만 적습니다.

> 디스코드 링크 설정 파일을 메모장으로 열어줘. 토큰은 내가 직접 바꿀게.

파일을 저장한 뒤 아래처럼 요청합니다.

> 설정 파일을 고쳤어. 디스코드 링크 점검해줘.

## 9. 반응이 없을 때

> 디스코드 스레드에 메시지를 보냈는데 세션이 반응하지 않아. 아래 순서로 원인을 찾아줘.
> 1. status 로 이 세션이 켜져 있고 리스너가 실행 중인지 확인
> 2. doctor 로 토큰, 채널 접근, 본문 읽기 권한 확인
> 3. link.log 의 최근 오류 확인 (토큰은 출력하지 말 것)
> 4. settings.json 에 discord-link 훅이 한 벌만 설치되어 있는지 확인
> 원인을 찾으면 고치기 전에 무엇을 바꿀지 먼저 설명해줘.

자주 나오는 원인은 다음과 같습니다.

- 봇이 메시지 본문을 읽지 못함: 디스코드 개발자 포털의 Bot 화면에서 **MESSAGE CONTENT INTENT** 를 켭니다.
- 턴이 끝나도 보고가 오지 않음: 설정 파일의 `min_report_interval` 이 크게 잡혀 있거나 훅이 설치되지 않은 경우입니다.
- 스레드가 만들어지지 않음: 봇에 Create Public Threads 와 Send Messages in Threads 권한이 없는 경우입니다.

## 10. 기능을 고치거나 더할 때

> discord-link 스킬에 <원하는 기능>을 추가해줘. 먼저 SKILL.md 와 dclink.py 의 관련 부분을 읽고, 바꿀 내용을 설명한 뒤 진행해줘.
> 수정 뒤에는 tests 폴더의 오프라인 테스트를 모두 다시 실행하고, 토큰은 어디에도 출력하지 마.

## 11. 제거하기

> discord-link 스킬을 제거해줘. 먼저 uninstall-hooks 로 settings.json 의 훅만 빼고, 스킬 폴더와 %USERPROFILE%\.discord-link 폴더는
> 지우기 전에 목록을 보여 주고 내 확인을 받아줘.

## 12. 안전 수칙

- 봇 채널은 본인만 들어가는 비공개 채널로 둡니다. 채널에 들어온 사람이면 누구의 메시지든 세션에 지시로 전달됩니다.
- 여러 사람이 있는 서버에 봇을 넣었다면 설정 파일 `[options]` 의 `allowed_user_ids =` 뒤에 내 디스코드 사용자 ID 를 적습니다. 그러면 내 메시지만 세션에 전달됩니다.
- 토큰이 노출되었으면 개발자 포털에서 곧바로 **Reset Token** 을 누르고 설정 파일의 값만 바꿉니다.
- 디스코드로 파일 삭제나 외부 전송 같은 위험한 작업을 지시하면, 스킬은 실행하기 전에 디스코드로 확인을 요청하도록 되어 있습니다.
