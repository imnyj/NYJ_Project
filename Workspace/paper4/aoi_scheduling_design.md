# AoI-aware V2I 업링크 갱신 스케줄링 — 설계·구현 명세

> **대상**: Antigravity CLI (coder/orchestrator 서브에이전트)
> **작업 규칙**: `.rules/coder.md`·`.rules/critic.md` 준수 — 코드는 `/code/`에서만, 각 구현 후 독립 검증 스크립트 실행, critic 검토. 모든 작업·기록은 한국어.
> **성격**: 이 문서는 새 연구 방향의 **자립적 설계 명세**다. 기존 `paper4`(V2X DCC)나 CIoV 콘텐츠 프리캐싱과는 **다른 주제**이며, 프레임워크(`NetSim.py`, `Communications.py`, SUMO 환경)만 재사용한다. 콘텐츠 캐싱/프리캐싱은 이 방향에서 **다루지 않는다**(재도입 금지).

---

## 0. 한 줄 정의

밀집 V2I 환경에서 차량들이 자기 상태를 RSU에 업링크로 갱신할 때, **RSU가 각 차량에게 "다음 갱신 시점·서브채널·전력"을 grant로 스케줄**하여 **유효 AoI(불필요한 갱신을 배제한 정보 신선도)와 망 혼잡을 동시에 최소화**하는 강화학습 스케줄러를 개발한다.

## 1. 배경·동기 (구현 판단에 필요한 최소 맥락)

- **왜 AoI인가**: 차량 상태정보는 가볍지만 다수·고빈도라, 모두가 자주 보내면 채널이 포화(충돌)되어 오히려 정보가 늦게/못 도달한다. 유한 자원 하에 "누구를 언제 갱신시킬지"가 문제이고, 목적함수가 AoI다. (콘텐츠가 무거워서가 아니라 **채널이 유한해서** 생기는 문제.)
- **왜 "유효" AoI인가 (핵심 기여)**: 순수 AoI(정보 나이)는 낭비를 부른다. 정지·정체 차량은 RSU가 마지막 상태를 외삽해도 실제와 안 어긋나므로 **나이가 많아도 갱신이 불필요**하다. 반대로 가·감속·회전 중인 차량은 몇 초만 지나도 추정이 크게 틀린다. 따라서 나이가 아니라 **추정 오차(estimation error / Age of Incorrect Information)** 를 최소화해야 하며, 스케줄러가 "동역학에 따라 다른 갱신 가치"를 학습하는 것이 순수 AoI 대비 이 논문의 delta다.
- **왜 grant 스케줄인가**: 고정 주기 폴링(예: 1초마다 전송)은 낭비이고 비정상 상황에 못 맞춘다. 대신 차량이 갱신을 보낼 때마다 RSU가 응답으로 **다음 갱신 시점을 되돌려주면**, 결정 시점·전송 시점·다음 상태 입력 시점이 한 점에 정렬되고 폴링 낭비가 사라진다.

## 2. 시스템 환경 (Environment)

- **공간**: 단일 RSU 셀(커버리지 반경 `r_cov`, 기존 SUMO 환경 재사용). 시변 집합 `V(t)`의 차량 `N(t)`대가 진입·이탈로 변동.
- **업링크 자원**: `C`개 서브채널 × 연속시간. 전송 성공 여부는 **SINR 확률 판정**(§4).
- **RSU 보유 상태**: 각 차량 `i`에 대해 마지막 수신 상태 `x̂_i`와 수신시각 `τ_i`.
- **Ground truth 분리**: SUMO(libsumo)는 실제 상태 `x_i^true(t)`를 제공 → **보상 계산에만** 사용. RSU가 결정 시 보는 것은 마지막 갱신값+맥락뿐 → **State는 RSU 관측치로만** 구성. 이 분리는 "예측 불필요" 방어선이자 방법론적 청결성의 핵심.

## 3. 최적화 목적 (Objective)

장기 평균으로 두 축을 동시 최소화:

```
min_π  E[ Σ_i w_i · c(e_i(t))        # (A) 유효 AoI: 불필요 갱신 방지
        + λ1 · CBR(t)                 # (B) 망 혼잡도 최소화
        + λ2 · (갱신 빈도) ]
```

- `e_i(t)`: RSU 추정치와 실제의 어긋남(§5). `c(·)`: 비용함수 (초기 확정=볼록 `e_i²`). 오차가 커질수록 기하급수적으로 패널티를 주어 큰 추정 오차(사고 위험 등)를 극단적으로 방지한다.
- `w_i`: 안전 중요도 가중(선택).
- **베이스라인 대비**: `c(e_i)=AoI_i`(순수 나이)를 베이스라인으로 두고, 제안(오차 기반)이 이를 이겨야 한다.

## 4. 통신 모델 — 확률적 SINR 충돌 (`Communications.py` 정합)

같은 서브채널·겹치는 시점에 전송하는 차량들을 간섭원으로 본다.

```
SINR_i = (p_i · g_{i,R}) / ( N0 + Σ_{j∈I(i)} p_j · g_{j,R} )
```

- `g_{·,R}`: 거리 기반 경로손실 + 페이딩 (기존 Wi-Fi 수신확률 로직 재사용).
- `I(i)`: `i`의 전송구간과 겹치는 **동일 서브채널** 전송자 집합.
- **성공확률** `P_succ_i = Pr(SINR_i ≥ γ_th)`.
  - 성공 → RSU가 상태 수신·`x̂_i, τ_i` 갱신.
  - 실패 → **미갱신**(오차 계속 누적) + 다음 grant까지 대기(짧은 재시도 grant 가능).
- **전력 trade-off(중요)**: `p_i`↑ → 자기 성공확률↑이지만 **타 차량 간섭↑**(남의 성공확률↓). 이 긴장이 혼잡 최소화 목적과 직접 연결된다. 결정론적 충돌(이진)로 하지 말 것 — 반드시 확률적으로.

## 5. 추정 오차 정의 (사후 소급 계산)

RSU는 마지막 갱신값을 **등속 외삽**한다:

```
x̂_i(t) = pos_{τ_i} + v_{τ_i} · (t − τ_i)
e_i(t) = || x_i^true(t) − x̂_i(t) ||
```

- 정지 차량: `v_{τ_i}≈0` → 외삽=실제 → `e_i≈0`(나이 무관). 기동 차량: 외삽 드리프트 → `e_i` 급증. (유효 AoI의 수식적 근거.)
- **사후 소급(결정 1 확정)**: RSU는 결정 시점엔 실제 오차를 모른다. **다음 갱신이 도착하면** 그 사이 구간 `[t_prev, t_now]`의 오차를 소급 계산하여 직전 grant의 보상을 확정한다. 온라인·실배포에서도 성립.

## 6. 시점 설계 — Event-driven (고정 슬롯 폴링 없음)

연속 시계 위 세 이벤트로만 구동:

- **E1 진입 `t_enter`**: 차량 `i`가 커버리지 진입 → 최초 상태 1회 전송(등록) → RSU가 첫 grant `(Δ_i, ch_i, p_i)` 회신. transition 시작.
- **E2 예정 갱신 `t_prev + Δ_i`**: 차량이 `(ch_i, p_i)`로 다음 상태 전송 → SINR 성공판정.
  - 성공: `x̂_i, τ_i` 갱신 → **직전 구간 오차 소급계산으로 reward 확정, transition 완성** → 새 상태로 다음 grant 산출.
  - 실패: 미갱신, 오차 누적 지속, 짧은 재시도 grant.
- **E3 이탈 `t_leave`**: 커버리지 이탈 → 미완 transition을 terminal(done=True)로 마감.

**정렬 원칙**: "결정 시점 = 전송 시점 = 다음 state 입력 시점"이 갱신 이벤트 한 점에 모인다.

## 7. State (grant 결정 시점, 차량별, RSU 관측치만)

| 그룹 | 피처 | 역할 | 출처 |
|---|---|---|---|
| 나이 | `AoI_i = t − τ_i` | 드리프트 누적 | RSU 기록 |
| 동역학 | 마지막 `v_i, a_i`, heading 변화율 | **오차 성장률 예측(정지=성장↓)** | libsumo |
| 신호맥락 | 다음 신호까지 거리·상태·잔여 위상 | 곧 정지/출발 예측 | getNextTLS |
| 로컬혼잡 | 차선 점유·앞차 수·큐 길이 | 저속 예측(오차 성장↓) | lane 데이터 |
| 채널 | RSU까지 거리→SINR 추정·성공확률 | grant 성공 가능성 | 위치+Wi-Fi 모델 |
| 전역 망상태 | 서브채널별 예약밀도, 현재 CBR, 임박 grant 수 | 충돌 회피·혼잡 근거 | 채널 상태 |

**금지**: State에 실제 오차 `e_i`를 넣지 말 것(결정 시 미관측). 오차는 보상 계산에만.

## 8. Action — grant 3-튜플 (Hybrid Action Space)

```
a_i = ( Δ_i , ch_i , p_i )
```
- `Δ_i`: 다음 갱신 간격 (**연속 공간**, Continuous). 작게=신선·혼잡↑ / 크게=혼잡↓·오차↑.
- `ch_i`: 서브채널 ∈ {1..C} (**이산 공간**, Discrete Categorical).
- `p_i`: 송신 전력 (**연속 공간**, Continuous).
- **혼합 행동 공간 (Hybrid Action Space)**: 이산적인 채널 할당과 연속적인 간격/전력 제어가 동시에 이루어지는 환경에 적합한 구조를 설계한다.

## 9. Reward (다음 갱신 이벤트에서 소급 확정)

```
R_i = − ∫_{t_prev}^{t_now} w_i · e_i(s) ds     # 유효 오차 누적 (정지=0)
      − λ1 · CBR_{[t_prev, t_now]}             # 망 혼잡
      − λ2                                     # 갱신 1회 비용
      − β · (1 − P_succ_i)                      # 전송 실패 기대 페널티(SINR)
```

- 오차 적분: SUMO ground truth로 계산. 정지 차량 ≈0 → 큰 `Δ` 줘도 손해 없음(불필요 갱신 방지 학습).
- 충돌이 잦은 grant는 `P_succ`↓ → 벌점↑ + 미갱신으로 오차도↑ → 이중 억제(혼잡 자연 회피).
- `λ1, λ2, β` 및 `c(·)` 형태는 튜너블(§13).

## 10. 에이전트 / 아키텍처

- **구현 프레임워크**: 자유로운 네트워크 구조 변경과 Actor/Learner 분리를 위해 **순수 PyTorch + CleanRL 스타일**을 채택한다.
- **알고리즘 벤치마크**: Action이 Hybrid 공간이므로, PPO, SAC, TD3 등 다양한 알고리즘의 혼합 액션(Hybrid) 버전을 모두 구현하고 베이스라인으로 학습시킨다.
- **Novel Architecture 탐색**: 베이스라인 확보 후, 기존 1차원 상태 벡터 입력(Flat Vector)에 1D-ResNet 등을 도입하거나 Actor-Critic 구조를 변경하여 최적의 자체 모델 구조를 도출한다.
- 상태 정규화 규약을 처음부터 일관되게 적용하여 피처가 죽는 현상을 방지한다. (거리는 `r_cov`, 시간은 `Δ`상한치, 개수는 밀도 상한)

## 11. 이중 모델 운용 (서비스 무중단 학습)

**구조**: actor(serving) / learner(training) 분리 + hot-swap.

1. **Serving 모델 `θ_serve`**: 모든 grant를 추론만으로 결정(가벼움). transition을 replay buffer에 축적.
2. **버퍼 충족 시**: `θ_learn`(=`θ_serve` 복사본)이 **별도 프로세스/코어**에서 학습.
3. **완료 시 hot-swap**: `θ_serve ← θ_learn`. 진행 중 이벤트는 이전 파라미터로 마무리 후 전환(무중단).

**자원 격리 (서비스 지장 방지) — 필수**:
- Learner는 별도 프로세스(GIL 회피) + CPU 코어 핀닝(taskset/cgroup)으로 serving 코어와 분리. GPU 있으면 학습=GPU, 서빙 추론=CPU.
- serving 프로세스 우선(nice↓), learner 양보(nice↑). replay buffer 크기 상한으로 RAM 캡.
- serving은 forward pass만, backprop은 learner에만.

**온라인 RL 함정 대비 (안 하면 리뷰에서 깨짐)**:
- 비정상성: swap 시 정책 급변 방지(soft-update/EMA 옵션) + 성능 회귀 시 롤백 가드.
- 분포 이동: serving에 소량 탐험(ε 작게) 유지.
- 재현성: **논문 결과는 학습 수렴 후 고정 정책으로 별도 평가 run에서 측정**(온라인 학습 중 지표와 분리).

## 12. 평가 베이스라인

- **순수 AoI 스케줄러**: `c(e_i)=AoI_i`. 동역학 무시, 오래된 것부터 갱신(정지 차량도 낭비). 제안이 이겨야 하는 핵심 대조군.
- **고정 주기**: 모든 차량 동일 `Δ`(예: 1 s) 갱신.
- **랜덤/그리디 서브채널·전력**.
- (선택) 기존 ETSI DCC류 rate 적응.

**핵심 지표**: 평균/최대 유효오차(estimation error), 평균/피크 AoI, 전송 성공률, CBR/충돌률, 갱신 횟수(자원 사용), 정지 차량 대상 불필요 갱신 비율(제안의 셀링 포인트).

## 13. 튜너블 파라미터

`C`(서브채널 수), `Δ`그리드, 전력 레벨, `γ_th`, `N0`, `λ1, λ2, β`, `c(·)` 형태(선형/볼록/임계 `δ`), `w_i`, 차량 밀도·진입률, `r_cov`, 학습 하이퍼파라미터, 버퍼 크기, hot-swap 조건.

## 14. 구현 로드맵 (build order + 검증 기준)

각 단계는 완료 후 **독립 검증 스크립트**로 확인하고 critic 검토를 받는다(.rules 준수). 실제 대규모 학습·평가는 워크스테이션에서.

- **[ ] S1. 환경 계층** (`/code/src` 위, `NetSim` 재사용)
  - E1/E2/E3 이벤트 훅, RSU의 `(x̂_i, τ_i)` 상태 유지, 등속 외삽 + **사후 오차 소급계산** 계측.
  - 검증: 정지 차량 `e_i≈0`, 기동 차량 `e_i` 증가가 시간에 따라 관측되는지 단위테스트.
- **[ ] S2. 통신 모델** (`Communications.py` 확장)
  - `C` 서브채널, grant `(Δ,ch,p)` 반영, 동일 서브채널·중첩 전송의 **SINR 성공확률** 판정.
  - 검증: 동시 전송 수·전력 증가 시 `P_succ` 저하가 단조적으로 나오는지 확인.
- **[ ] S3. 에이전트 인터페이스**
  - State 벡터화(정규화 포함), grant action 디코딩, transition/reward 조립(소급 오차 적분 + CBR + 실패 페널티).
  - 검증: 한 차량의 (grant→전송→소급보상) 사이클이 값으로 재현되는지.
- **[ ] S4. 학습 루프 + 베이스라인 모델 구축**
  - PyTorch/CleanRL 기반 학습 루프, Hybrid PPO/SAC/TD3 베이스라인 구현, 모델 분리 및 hot-swap 로직.
  - 검증: 학습 프로세스가 serving 결정 지연에 영향 주지 않음(지연 측정), swap 전후 서비스 무중단.

## 부록: 한눈에 보는 확정 설계

- **환경**: 단일 RSU 셀, 가변 N대, `C` 서브채널, SINR 확률 성공.
- **목적**: 유효 AoI(추정오차) + 망 혼잡 최소화.
- **시점**: event-driven (진입/예정 갱신/이탈), 폴링 없음.
- **State**: 차량별 [나이·동역학·신호·로컬혼잡·채널·전역 망상태] (1D Flat Vector).
- **Action**: grant `(Δ, ch, p)` 혼합 공간 (연속 Δ/p + 이산 ch).
- **Reward**: `−∫e_i² − λ1·CBR − λ2 − β(1−P_succ)` (t_now에 소급 확정, 2차 함수).
- **운용**: Actor/Learner 분리 + Hot-swap + 자원 격리 (PyTorch+CleanRL 기반).
- **베이스라인**: 알고리즘(Hybrid PPO, SAC, TD3) 및 스케줄러(순수 AoI / 고정주기 / 랜덤).
