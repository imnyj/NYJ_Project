## 시나리오

Cellular로 모든 차량의 이동성을 관리하기에는 cost 부담.
Roadside unit(RSU)가 갱신이 필요한 차량에 한하여 update하여 AoI를 최신화하기 위해 관리.

차량은 RSU의 통신범위 진입 시, RSU와 연결 시도
RSU는 충돌 회피를 통하여 차량으로부터 현재 이동성 정보 등을 건네 받고 정보를 입력 및 갱신함.
이후 차량의 다음 갱신 타이밍 등을 결정하여 차량에게 전달함.
보상에 따라서 더 효율적인 선택을 유도.
RSU의 통신 범위를 나갈 때까지 해당 차량은 계속해서 차량 각각에게 재갱신 타이밍을 부여.

* State
Paper1의 ST-MBAN에서 고려했던 30차원의 feature vector 중 필요한 것 사용.
 - 의미 있는 데이터인지
 - 해당 x를 위한 cost(delay, power 등)가 더 크진 않은지

* Action
갱신 타이밍과 전력은 continuous variables로 설정
서브 채널 선택
등

* Reward
정지 상태인 차량은 AoI를 최신화할 필요 없음.
 - 신호등 상태, 신호등 변경까지 남은 시간, 해당 차선 중 앞에 차량이 몇대 있는지, 출발 가속도와 시점은 언제가 될지에 따라 추론이 될 것 같다고 생각.
너무 잦은 갱신으로 AoI를 무작정 최신화 해봤자 전력만 낭비되며 congestion 및 충돌 증가.
등

* 모델 운용
Act mode / Rest mode를 두어서
Act mode 모델이 강화학습 모델을 기반으로 서비스하면서 batch 채움
batch가 가득 차면 Rest mode 모델이 학습 시작
Rest mode 모델의 학습이 완료되면, Act mode 였던 모델은 마지막 State를 서비스한 뒤 Rest mode로 변환.
학습이 완료된 모델은 Act mode가 되어 그 뒤 State를 이어받아서 서비스 제공.

이때, HW feasibility를 측정하여 학습 리소스가 추론 리소스에 영향이 가지 않도록 조심해야 함.
또한, 추론 시간이 충분히 짧아야 함.

* Baselines (최신은 2025, 2026년도 기준으로 함)
- 기본 모델 3개: PPO, SAC, TD3
- 최신 모델 3개: MAPPO 등
- 가장 비슷한 모델 3개

* Baselines의 최적화를 위해 optuna 사용
 - 각 방안별로 주요 하이퍼파라미터 파악(PPO는 clip_rate 등)
 - 각 방안별로 최적화된 하이퍼파라미터를 optuna로 찾기
 - 각 모델별로 찾은 하이퍼파라미터를 csv로 저장

* 제안 방안 설계 (이 단계의 시작에는 사용자의 허용 필요)
 - 비교 방안들과 성능을 비교해가며 최고의 모델 연구 시작
