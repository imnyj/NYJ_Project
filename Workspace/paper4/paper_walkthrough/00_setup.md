# 0단계. 사전 준비

## 목적

논문 프로젝트의 작업 공간, 규칙 파일, 7인 서브에이전트 팀, 진행 상태 파일을 준비합니다. 한 세션이 모든 일을 하는 대신
역할을 나눈 팀으로 일해야 결과의 신뢰도가 올라가고, 팀이 7인을 넘으면 방향이 흩어지기 쉽기 때문에 7인으로 고정합니다.

## 들어가기 전 조건

- 사용자가 논문 번호(paperN)를 알려 주었습니다. 알려 주지 않았다면 먼저 묻습니다.

## 절차

1. **[사용자 결정]** 프로젝트 번호와 폴더 이름을 확인합니다. 사용자가 이미 알려 주었으면 다시 묻지 않고, 알려 주지 않았을 때만 묻습니다. `/home/imnyj/Workspace/paperN/` 이 이미 있으면 그 구조를 따르고, 없으면 사용자 확인을 받은 뒤 만듭니다.
2. 기존 폴더가 없다면 아래 구성을 만듭니다. 프로젝트 `.rules/` 에 다른 경로가 정해져 있으면 그 경로를 따릅니다.

   | 경로 | 용도 | 주로 쓰는 역할 |
   |---|---|---|
   | `.rules/` | 역할별 절대 규칙 7개 | 모든 역할 |
   | `idea/` | 아이디어 최신본과 변경 기록 | idea(내용), worker(기록) |
   | `librarian/` | 문헌 JSON, 비교 방안 근거 | librarian |
   | `code/` | 시뮬레이션과 모델 코드 | coder |
   | `data/` | 실험 결과 CSV, 체크포인트, 수렴 모델 | coder |
   | `visualizer/` | 그래프 규격(`config.md`)과 그래프 산출물 | visualizer |
   | `writer/` | 원고(LaTeX) | writer |
   | `review/` | critic 과 idea 의 검토 보고서(worker 가 기록) | worker |
   | `backup/` | 이전 판과 폐기 파일 | worker |
   | `etc/scripts/`, `etc/logs/`, `etc/temp/` | 보조 스크립트, 실행 로그, 임시 파일 | 모든 역할 |

3. **[사용자 결정]** 팀 규칙을 복제할 기존 프로젝트를 고릅니다. 기본 추천은 가장 최근에 정비한 `paper4/.rules/` 입니다.
   복제한 뒤 경로와 프로젝트 고유 내용(시나리오 이름, 모델 이름 등)만 바꿉니다. 그리고 `.rules/` 에 적힌 경로(예: `/code/`, `/data/`)와 실제 폴더 구성이
   일치하는지 확인합니다. paper4 는 규칙 파일이 `/code/` 를 지시하지만 실제 폴더는 `coder/` 여서 이미 어긋나 있으므로, 새 프로젝트에서는 둘 중 하나로 맞춥니다.
4. `~/.claude/agents/` 에 `pN-coder`, `pN-critic`, `pN-idea`, `pN-librarian`, `pN-visualizer`, `pN-worker`, `pN-writer` 정의 파일을 만듭니다.
   프론트매터 형식, 역할별 도구, 색상, `background: true` 는 전역 CLAUDE.md 3부의 "에이전트 정의 파일 규격" 을 그대로 따릅니다.
   critic 과 idea 에게는 쓰기 도구를 주지 않고, visualizer 에게는 Bash 를 주지 않습니다. 그래서 critic 과 idea 가 낸 보고서와 기록할 내용은 worker 가 파일로 씁니다.
   만든 뒤 Agent 도구의 에이전트 목록에 `pN-*` 7개가 보이는지 확인합니다. 보이지 않으면 `WALKTHROUGH_STATE.md` 를 갱신하고 사용자에게 세션 재시작을 요청합니다.
5. 역할별 핵심 규칙이 규칙 파일에 들어 있는지 확인합니다.
   - coder: 모든 자료를 파일로 기록하고 필요할 때 다시 읽는다. `code/` 에서만 코드를 쓰고 `data/` 에만 데이터를 쌓는다. 코드를 완성하면 critic 의 검토를 받는다.
   - critic: coder 와 writer 의 결과물에서 고칠 점을 집요하게 추적하고 수정 지침을 낸다. 직접 고치지 않는다.
   - idea: 제안 방안 아이디어의 판과 변경을 판단해 보고서로 낸다. 쓰기 도구가 없으므로 파일 기록은 worker 가 한다.
   - librarian: 문헌 검색과 검증 규칙(2단계 파일 참조)을 지키고 bibitem JSON 을 관리한다.
   - visualizer: 비교 방안과 제안 방안의 이름, 색상, 순서를 지킨다. 그래프 제목을 넣지 않는다. 축, 라벨, 범례, 글꼴 크기를 학술적이고 일관되게 맞춘다. 같은 결과물은 덮어쓴다.
   - worker: 파일 이동, 복사, 백업 격리 같은 단순 작업과 critic, idea 보고서의 파일 기록을 처리한다.
   - writer: LaTeX 로 섹션 초안을 쓰고 학술 문체를 지킨다(8단계 파일 참조).

   **[사용자 결정]** 원문은 worker 에 가장 낮은 모델을 권하지만, 전역 규격은 모든 역할이 `model: inherit` 입니다. worker 에 낮은 모델을 지정할지 묻습니다.
6. `visualizer/config.md` 에 그래프 색상 팔레트를 적어 둡니다. 모델별 배정은 4단계에서 사용자 결정을 받아 채웁니다.

   | 번호 | RGB | HEX |
   |---|---|---|
   | 1 | 255, 80, 80 | #FF5050 |
   | 2 | 237, 125, 49 | #ED7D31 |
   | 3 | 255, 153, 102 | #FF9966 |
   | 4 | 255, 192, 0 | #FFC000 |
   | 5 | 204, 204, 0 | #CCCC00 |
   | 6 | 112, 173, 71 | #70AD47 |
   | 7 | 0, 204, 153 | #00CC99 |
   | 8 | 51, 153, 255 | #3399FF |
   | 9 | 0, 102, 255 | #0066FF |
   | 10 | 102, 102, 255 | #6666FF |
   | 11 | 204, 102, 255 | #CC66FF |
   | 12 | 255, 102, 255 | #FF66FF |
   | 13 | 255, 0, 0 | #FF0000 |

7. **[사용자 결정]** 디스코드로 진행 보고를 받을지, 받는다면 보고 시각(기본 6시, 12시, 18시, 24시)을 정합니다. 받는다면 `/discord-bridge` 로 이 세션을 연결합니다.
8. **[사용자 결정]** 문헌 검색에서 긴 대기 시간(5시간, 20시간, 24시간 등)을 받았을 때의 재시도 간격을 정합니다. 원문에는 "1분 뒤 최대 5번" 과 "10초 뒤 최대 5번" 이 함께 적혀 있습니다.
   정한 값은 `librarian` 규칙 파일에 적습니다.
9. GPU 사용 현황(세션 시작 요약의 `[gpu]` 줄)과 가상 환경(`/home/imnyj/venv`)을 확인합니다.
10. 프로젝트 루트에 `WALKTHROUGH_STATE.md` 를 만듭니다(입구 파일 7절 양식).

## 산출물

- `~/.claude/agents/pN-*.md` 7개 파일
- `WALKTHROUGH_STATE.md`

## 완료 조건

- 위 파일이 모두 절대 경로로 존재하고, 에이전트 정의 파일의 프론트매터(name, tools, color, background)가 규격과 일치합니다.
- 현재 세션에서 `pN-*` 에이전트를 호출할 수 있습니다.
- 상태 파일에 0단계 결정 사항(프로젝트 번호, 복제 기준, worker 모델, 보고 방식, 재시도 간격)이 기록되어 있습니다.
