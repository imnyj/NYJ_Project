# 1단계. 대략적인 아이디어 설정

## 목적

어떤 환경에서, 무엇이, 무엇을 위해, 어떤 방안을 쓰는지 대략적인 틀을 잡습니다. 나중에 큰 틀이 바뀌더라도 일단 틀이 있어야
논문 탐색이 쉬워집니다. "논문을 써야 하니 작업해 줘" 처럼 범위가 넓은 요청으로는 진행이 어렵기 때문에, 이 단계에서 범위를 좁힙니다.

## 들어가기 전 조건

- 0단계 완료 조건을 통과했습니다.

## 참여 역할

idea(방향 판단), librarian(트렌드 조사), worker(기록)

## 절차

1. 사용자가 아이디어를 주었다면 아래 네 항목으로 정리합니다. 빠진 항목이 있으면 **[사용자 결정]** 으로 묻습니다.
   - 시나리오: 어떤 환경에서 무엇이 무엇을 위해 어떤 것을 하는지 한 문장으로 적습니다.
     예) Content-Centric Vehicular Networks 에서 차량이 다음에 진입할 RSU 에 content 를 얼마나 precaching 할지에 대한 예측 정확도를 높이는 지도 학습 방안.
   - 목표: 어떤 지표를 최적화할지 적습니다.
   - 시뮬레이션이나 실험에 대한 구체적인 지시를 적습니다.
   - 시나리오에 대한 상세한 설명을 적습니다.
2. 사용자가 연구 분야를 아직 정하지 못했다면, 관심 분야를 받아 최근 연구 트렌드를 조사합니다. 조사 요청에는 연도를 숫자로 적습니다(예: "2024년부터 2026년까지").
   찾은 논문은 DOI 로 검증하고 JSON 에 저장합니다(검색 규칙은 2단계 파일 참조). 조사 결과를 방향 후보 2~4개로 정리해 **[사용자 결정]** 으로 고르게 합니다.
3. 아이디어 설명이 길면 더 상위 모델을 쓰는 편이 좋고, 사용자가 md 파일로 써서 건넬 수도 있습니다. 이때 파일을 읽고 네 항목으로 다시 정리해 사용자에게 확인받습니다.
4. idea 가 아이디어 최신본과 변경 사유를 보고서로 내면 worker 가 `idea/idea.md` 에 기록합니다. 아이디어가 바뀔 때마다 worker 가 이전 판을 `backup/idea/` 로 옮기고,
   `idea/CHANGELOG.md` 에 날짜, 바뀐 내용, 바꾼 이유를 한 줄씩 남깁니다.
5. 프로젝트 루트에 `sketch.md` 를 만듭니다. 이후 `/goal sketch.md 를 읽고 작업을 순서대로 시작해` 처럼 이 파일 하나로 작업을 지시할 수 있게 하는 것이 목적입니다.
   `sketch.md` 에는 시나리오, 목표 지표, 시뮬레이션 지시, 상세 설명, 그리고 아래 체크리스트를 담습니다.

```markdown
## 순서
- [ ] 시뮬레이션 구현
- [ ] 관련 주제의 논문 조사 (Related Works 확보, 아이디어 참신성 검증): 찾은 논문은 cite 하기 좋게 JSON 으로 관리
- [ ] 목표를 위한 최적의 방안 찾기: 2026년까지의 최신 논문보다 성능이 떨어지지 않는 방안을 찾는다. ML 이나 DL 모델의 하이퍼파라미터는 optuna 로 최적화한다.
```

   체크리스트는 원본 명령의 순서를 옮긴 것이고, 실제 진행 순서는 이 안내서의 단계 순서(2단계 문헌 조사 → 3단계 시뮬레이션)를 따릅니다.
6. **[사용자 결정]** 정리한 `idea/idea.md` 와 `sketch.md` 를 보여 주고 방향을 승인받습니다.

## 산출물

- `idea/idea.md`, `idea/CHANGELOG.md`, `sketch.md`
- 트렌드 조사를 했다면 `librarian/trend_survey.md` 와 검증된 문헌 JSON

## 완료 조건

- 시나리오, 목표 지표, 시뮬레이션 지시, 상세 설명이 모두 채워져 있습니다.
- 사용자가 방향을 승인했고, 그 기록이 `WALKTHROUGH_STATE.md` 에 있습니다.

## 사용자 명령 예시

> /goal sketch.md 를 읽고 작업을 순서대로 시작하도록 해.

> /goal (1) 시뮬레이션 구현. (2) 시뮬레이션 검증. (3) 환경 변수를 운용할 수 있게 config.md 운용. (4) 최근(2026)까지 해당 방안에 대해 어떤 연구가 되었는지 찾아서 JSON 파일로 정리. (5) 최적의 모델에 대한 방안 구상.

두 번째 명령처럼 사용자가 여러 단계를 한 번에 지시하면, 이 안내서의 해당 단계 파일(2, 3단계)을 차례로 읽으며 진행하고 각 단계의 사용자 결정 지점에서는 여전히 멈춥니다.
