## 결함 1 [치명] Δ(갱신 타이밍) 액션이 환경에서 완전히 무시된다

`hot_swap_trainer.py::AoiV2IEnv.step()`은 `action_dict`에 들어온 **모든 차량을 매 스텝(0.1초) 무조건 전송**시킨다.
`delta`는 `:1127`에서 디코딩되어 `:1148`의 `tx_item["delta"]`에 저장되지만, **코드베이스 어디에서도 읽히지 않는다**
(`grep '\["delta"\]'` → 0건). 다음 갱신 시각을 잡는 로직 자체가 없다.

훈련 루프(`:1701-1715`)도 매 스텝 전 차량에 `decide_grant`를 호출하고 `grant[0]`(=Δ)는 `ep_aois` 리스트에
넣기만 한 뒤 버린다(`ep_aois`는 이후 사용처 없음).

### 실측 증거

동일 시드(42)로 Δ만 극단적으로 바꿔 400스텝씩 실행:

| | Δ = 0.1 s (매 스텝 갱신) | Δ = 45.0 s (45초에 한 번) |
|---|---|---|
| tx_attempts | 4407 | **4407** |
| tx_fails | 1053 | **1053** |
| packet_loss | 0.2389 | **0.2389** |
| mean_cbr | 0.01234 | **0.01234** |
| mean_error | 7.8484 | **7.8484** |

450배 차이 나는 액션이 **모든 지표에서 완전히 동일**하다. Δ는 inert.

이것이 `simulation_plan.md`의 사전점검(16:14)에서 4개 모델이 전부 `tx_attempts=305`로 같았고,
사후점검(16:46)에서 PPO와 MA2HDQN이 전부 `tx_attempts=4407`로 같았던 이유다.
서로 다른 정책이 같은 전송 횟수를 내는 것은 정상일 수 없는데, 그 신호를 놓친 채 "정상 판정"이 내려졌다.

### 원인

감사를 받은(그러나 실행되지 않는) `src/aoi_env.py`에는 Δ 스케줄링이 **정상 구현되어 있다**:

```
aoi_env.py:849   rec["next_update_t"] = current_time + grant_delta
aoi_env.py:783   if current_time >= rec["next_update_t"]:     # 이때만 전송
```

2026-08-27에 4대 anti-mocking 단언문을 실사용 클래스로 이식할 때, **Δ 스케줄링은 함께 이식되지 않았다.**
`Conversation.md` 5번 항목이 "[잔여] 복제 클래스 자체는 남아 있음"이라고 적어둔 그 미해결 항목의 실제 대가다.

### 영향

- 논문의 1차 기여(AoI 인지 갱신 주기 최적화)가 학습 자체가 불가능하다.
- 하이브리드 액션 3축 중 가장 중요한 축이 무보상 무제약 → 어떤 모델이든 Δ에 대해 임의값을 낸다.
- Δ와 혼잡의 결합(에어타임 모델을 도입한 목적)이 성립하지 않는다. CBR은 Δ가 아니라 "범위 내 차량 수"만의 함수다.

## 결함 2 [치명] AoI 지표가 `max(1.0, ·)` 클램프로 포화되어 상수다

`hot_swap_trainer.py:1257` `age = max(1.0, self.sim_time - track["t_update"])`

결함 1로 인해 모든 차량이 매 스텝 갱신되므로 실제 age는 평균 **0.0437초**(p95 0.20, max 1.30)다.
관측의 **98.8%가 1.0으로 잘려나간다.** 결과적으로 `mean_aoi = peak_aoi = 1.0017`, 고유값 6개.
**AoI 논문인데 AoI가 사실상 상수다.**

### 파생 오염: 추정 오차와 보상

dead reckoning이 클램프된 age로 외삽된다(`:1258-1259`):
`hat = pos_last + vel × age` 인데 age는 1.0초, 실제 경과는 0.1초.
따라서 오차는 "1초 앞을 예측한 값 vs 0.1초 뒤 실제 위치"의 차이가 되어 대략 `v × 0.9s ≈ 9 m`가 항상 발생한다.
실측 mean_error 6.78~7.85 m는 물리적 예측 오차가 아니라 **클램프 아티팩트**다.

600스텝 보상 분해 실측(w=0.5/0.2/0.2/0.1, 샘플 12,532건, 평균 보상 −0.3692):

| 항 | 정규화 평균 | 가중 기여 | 보상 내 비중 |
|---|---|---|---|
| r_err | 0.52143 | 0.26071 | **70.62%** |
| r_power | 0.38462 | 0.07692 | 20.83% |
| cbr | 0.15444 | 0.03089 | 8.37% |
| i_redundant | 0.00678 | 0.00068 | **0.18%** |

보상의 70%가 아티팩트다. 이 상태로 학습하면 모델은 "가짜 오차를 줄이는 법"을 배운다.

## 결함 3 [중대] I_redundant가 순서 문제로 구조적으로 억제된다

`_is_redundant_update()`는 `libsumo.simulationStep()` **이전**인 `:1139`에서 호출된다.
그 시점의 `self.sim_time`은 아직 직전 스텝의 값이다. 직전 스텝에 전송이 성공한 차량은
`track["t_update"] == self.sim_time`이므로 가드
`if float(track.get("t_update", self.sim_time)) >= self.sim_time: return 0.0`
에 걸려 **무조건 0을 반환한다.**

즉 매 스텝 갱신에 성공하는 정지 차량 — 논문이 겨냥하는 바로 그 사례 — 은 절대 redundant로 잡히지 않는다.
직전 전송이 *실패*했을 때만 발화한다.

실측: 정지(<0.1 m/s) 관측 비율 **5.80%**인데 I_redundant 발화는 **0.68%(85/12,532)**, 보상 기여 **0.18%**.
`Conversation.md` 3번이 "물리적 상태 불변 시 부과되는 **강력한 명시적** 패널티"라 규정한 항이
보상에서 사실상 존재하지 않는다.

## 결함 5 [최치명] 학습에 실제로 쓰이는 보상은 승인된 4항 보상이 아니다

보상 함수가 **두 개** 존재하고, 리플레이 버퍼에 들어가는 쪽은 설계 승인본이 아니다.

- `AoiV2IEnv.step()`이 계산하는 승인된 4항 보상
  `R = −(w1·Norm(e²) + w2·Norm(P) + w3·Norm(CBR) + w4·I_redundant)` 는
  훈련 루프에서 `ep_rewards.append(r)`(`:1720`)로 **로그에만** 쓰이고 버퍼에 들어가지 않는다.
- 실제로 `TransitionStreamer.push`되는 것은 `RLScheduler.decide_grant`가 자체 계산하는
  `reward = −(alpha_aoi·dt + beta_error·err + gamma_power·norm_power)` (`:511`)이다.
  항이 3개뿐이고 **CBR도 I_redundant도 없다.**

게다가 그 3항 중 2개가 상수로 죽어 있다.

- `err = st.get("estimation_error", 0.0)` — 훈련 루프(`:1706-1711`)가 `decide_grant`에 넘기는 dict는
  `{vid, current_time, pos, speed}` 4개뿐이라 `estimation_error` 키가 **아예 없다 → 항상 0.0**.
- `dt = max(0.1, cur_t − prev["time"])` — 결함 1로 매 스텝 호출되므로 **항상 0.1**.

따라서 학습 신호는 `−(0.1×0.1 + 0 + 0.01×norm_power) = −(0.01 + 0.01·norm_power)` 로 축약된다.

### 실측 증거 (PPO, 400스텝, 버퍼 push 가로채기)

```
버퍼에 실제 들어간 보상 : n=4374, 범위 [-0.02000, -0.01000], 평균 -0.01347
버퍼 delta_t            : 고유값 1개, 값 0.1  (γ^Δ SMDP 할인이 상수가 되어 무의미)
환경이 계산한 4항 보상  : mean_step_reward = -0.3971  (버퍼에 들어가지 않음)
```

범위가 정확히 `[-0.02, -0.01]`이라는 것은 **송신 전력을 제외한 모든 항이 0**임을 뜻한다.
즉 9종 baseline은 20만 스텝을 돌려도 "전력을 낮춰라" 하나만 학습한다.
AoI도, 오차도, 혼잡도, 중복 갱신도 학습 목표에 존재하지 않는다.

## 검증 결과 문제 없는 항목 (재확인 완료)

`simulation_plan.md` rev.2가 주장한 PHY 정교화는 **실제로 정확하다.** 직접 재계산해 확인했다.

- OFDM 심볼 8 µs, 6 Mbps(QPSK 1/2) = 48 bits/symbol → 300 B 프레임 = 16+2400+6 = 2422 bit
  → ⌈2422/48⌉ = 51 심볼 → 40 µs + 8 µs×51 = **448 µs**. 문서 값과 일치.
- 잡음바닥 −174 + 10log₁₀(10⁷) + 9 = **−95.0 dBm**. 일치.
- `SINR_TH_DB`가 리터럴이 아니라 `MCS_TABLE[6.0].req_sinr_db`에서 유도됨 → 레이트와 임계가 어긋날 수 없음. 좋은 설계.
- 안테나 이득 3 dBi(차량) / 9 dBi(RSU)가 `rx_power_dbm`에 실제 반영됨.
- 취약구간 겹침 확률 `2·T_air/T_step = 2×448µs/0.1s = 0.896%` — 모델 타당.
- 섀도잉 전용 RNG 분리(전역 `random` 스트림 오염 회피) — 재현성 측면에서 옳은 처리.
- anti-mocking 단언문 4종이 실사용 클래스에 실제로 존재하고 동작.

문헌 9종의 DOI 검증 기록(`librarian/baselines_v2.json`, `Conversation.md` 4번)도 형식상 문제없다.

## 권고 조치 순서 (훈련 착수 전 필수)

1. **Δ 게이팅 구현** — `aoi_env.py`의 `next_update_t` 방식을 실사용 클래스에 이식.
   차량별 `next_update_t`를 유지하고 `sim_time >= next_update_t`인 차량만 전송 대기열에 넣는다.
   설계 결정이 필요한 지점이 있어 사용자 확인 후 착수한다(아래 참조).
2. **age 클램프 제거** — `max(1.0, ·)` → 실제 경과 시간. 외삽·오차·보상이 동시에 정상화된다.
3. **I_redundant 순서 교정** — 판정을 `simulationStep()` 이후로 옮기거나, 가드를 `>` 대신 `>=` 기준
   직전-스텝 허용으로 완화. 정지 차량이 갱신을 받을 때 반드시 발화해야 한다.
4. 1~3 수정 후 **관측 벡터 liveness 재검사**(`etc/scripts/verify_observation_liveness.py`).
   특히 `vec[0] = age/10`은 현재 거의 상수 0.01이므로 5번째 죽은 피처에 해당한다. 수정 후 살아나는지 확인.
5. 그 다음에 20만 스텝 착수.

### 사용자 확인이 필요한 설계 분기 (Δ 게이팅)

Δ를 살릴 때 "갱신을 받지 않는 스텝"의 처리 방식이 결과를 크게 바꾼다.

- **(가) 순수 SMDP** — Δ만큼 침묵하고, 그 구간의 오차 누적을 다음 결정 시점에 한 번에 정산.
  `aoi_env.py`의 기존 구현과 가장 가깝고 논문 서사(갱신 주기 최적화)에 정합적.
- **(나) 매 스텝 보상, 전송만 게이팅** — 전송은 Δ에 따라만 일어나되 보상은 매 스텝 계산.
  현재 코드 구조 변경이 작고 학습 신호가 조밀하다. 다만 SMDP 할인(γ^Δ)과 의미가 어긋난다.

권고는 **(가)**. `rl_interface.py`에 이미 SMDP 후향적 버퍼와 γ^Δ가 있어 설계 의도가 (가)이며,
(나)로 가면 Δ가 길수록 무조건 유리해지는 퇴화 위험이 있다.
