# 2단계. 관련 논문과 비교 방안 찾기

## 목적

비슷한 최신 논문이 있는지, 더 좋은 방안이 있는지, 이 주제가 연구되고 있는지 조사하고, 성능을 비교할 방안을 정합니다.
여기서 모은 논문은 나중에 Related Works 와 서론의 인용에 그대로 쓰므로, 인용에 필요한 정확한 정보를 처음부터 검증해 둡니다.

## 들어가기 전 조건

- 1단계에서 승인받은 `idea/idea.md` 와 `sketch.md` 가 있습니다.

## 참여 역할

librarian(검색과 검증), critic(검증 표본 점검), idea(참신성 판단), worker(파일 정리와 기록)

## 검색 규칙 (librarian 규칙 파일에도 적습니다)

- IEEE, ACM, Elsevier(ScienceDirect) 같은 저명한 출판사의 논문만 검색합니다. Scopus, MDPI, arXiv 에서는 검색하지 않습니다.
- 오늘 날짜 기준 3년 이내 논문을 우선하고, 없으면 5년 이내로 넓힙니다. 분야의 초석이 되는 논문은 연도와 상관없이 씁니다.
- 검색은 1초에 1건만 합니다. IEEE 는 초당 1건 검색을 허용하고, API 키를 쓰면 이 속도를 안정적으로 보장받습니다.
- 긴 대기 시간(5시간, 20시간, 24시간 등)을 받으면 0단계에서 정한 간격만큼 기다렸다가 다시 시도하고, 5번 연속 실패하면 멈추고 보고합니다.
- 찾은 논문은 웹에 다시 접근하는 과정에서 환각이 생길 수 있으므로 반드시 DOI 로 직접 조회해 교차 검증합니다. 검증하지 못한 논문은 목록에 넣지 않습니다.

## bibitem JSON 형식

검증이 끝난 항목만 `librarian/references.json` 에 넣습니다.

- 저널: 모든 저자, 제목, 저널명, vol, no, pages, year, doi, 논문 요약 3문장
- 학회: 모든 저자, 제목, 학회명, 개최 장소, pages, year, doi, 논문 요약 3문장

## 절차

1. 아래 범주로 검색합니다. 원문의 두 방식을 모두 담았으며, 어느 방식을 쓸지와 범주별 개수는 **[사용자 결정]** 으로 정합니다.
   - 방식 A: 최신 논문 3편, 가장 유사한 논문 3편, 기본 방안 3편
   - 방식 B(RL 계열 예시): 기본 RL 모델 3개, 기본 DRL 모델 3개, 2026년까지의 최신 모델 3개, 추가 모델 3개
2. 범주에 들지 않더라도 쓸 만한 논문은 `librarian/related_works.json` 에 따로 모아 Related Works 에 쓸 수 있게 합니다.
3. 가장 유사한 논문들과 제안 아이디어의 차이를 표로 정리합니다(`librarian/novelty_check.md`). 차이가 약하면 **[사용자 결정]** 으로 아이디어를 고칠지 묻고,
   고치면 idea 가 갱신할 내용을 보고서로 내고 worker 가 `idea/idea.md` 와 `idea/CHANGELOG.md` 에 기록합니다.
4. 비교 방안 후보를 `comparative_methods.md` 에 정리합니다. 방안마다 범주, 근거 논문(JSON 키), 고른 이유, 구현 근거(공식 코드나 GitHub 주소)를 적습니다.
5. critic 이 `references.json` 에서 표본을 골라 DOI 를 다시 조회해 저자, 제목, 연도, 쪽수가 맞는지 확인합니다. 틀린 항목이 있으면 전수 재검증합니다.
6. **[사용자 결정]** 비교 방안 최종 목록을 승인받습니다.

## 산출물

- `librarian/references.json`, `librarian/related_works.json`, `librarian/novelty_check.md`
- `comparative_methods.md`

## 완료 조건

- 모든 JSON 항목이 DOI 로 검증되었고, critic 의 표본 점검 보고서가 `review/` 에 있습니다.
- 사용자가 비교 방안 목록을 승인했습니다.

## 되돌아가기 조건

- 이후 단계에서 비교 방안의 근거 논문이 존재하지 않거나 내용이 다르다고 밝혀지면 이 단계로 돌아와 목록을 다시 정합니다.

## 사용자 명령 예시

> /goal 기본 RL 모델 3개, 기본 DRL 모델 3개, 최신(~2026) 모델 3개, 추가 모델 3개를 찾아서 리스트를 파일로 정리하고 관리하도록 해. 그 후 제안 방안과의 성능을 비교해보도록 해.
> 만일 ML 이나 DL 모델이라면 하이퍼파라미터나 파라미터 최적화는 optuna 로 진행하여 효율성을 올려.
